# Architecture

TreasuryPilot is a single FastAPI service plus a React/Vite client and PostgreSQL persistence. The Airwallex adapter owns authentication and bounded read operations. Deterministic services normalize transfer states and evaluate reserve feasibility with `Decimal`. External user text remains data. The AI layer is optional and cannot authorize writes.

Current local milestone: API research, deterministic treasury engine, transfer status mapping, authenticated API boundary, Airwallex adapter for balances, transfer and beneficiary retrieval/listing plus an unexposed single-attempt create/validate client, and a durable unexposed operation lifecycle for stable request IDs, idempotent preparation, matching verified original evidence, action-bound maker-checker approval, and conservative reconciliation. Preparation rejects original evidence older than five minutes, and a unique database reservation prevents separate incidents from preparing recovery for the same original transfer. It is restricted to same-currency transfers to saved beneficiaries. Approval is bound to the exact prepared request hash, fresh original evidence version, and current treasury policy version; the policy-admin role must differ from the requesting operator, and approval is consumed once before the internal submission transition. Beneficiary retrieval is linked to verified transfer evidence and persists a PII-minimized audited summary. Operator-entered obligations, versioned currency policies, persisted live-plan results, audit events, and a React dashboard are also present. Live planning combines fresh Airwallex balances with local obligations/policies and fails closed on unknown fees, missing policy/balance, or ambiguous source accounts. The synthetic planner remains stateless and separate from user records and bank data. The operation and approval services have no API route; no user-facing approval or write workflow exists. Airwallex documents fees on the transfer response, and the validation endpoint does not provide a fee quote; fee uncertainty blocks recovery before a write. Airwallex credentials are present in the backend environment, but login returns HTTP 403 (`permission`), so no successful reads are verified.
